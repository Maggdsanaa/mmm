# نظام الحضور الجامعي بـ NFC

**لا خادم تملكه.** المسؤول والدكتور يتزامنان تلقائيًا عبر قاعدة Firebase مجانية (مجرد وسيط، وكل ما فيها مشفّر)،
والحضور نفسه بين هاتفي الطالب والدكتور عبر NFC **بدون إنترنت**.

| المكوّن | الدور |
|---|---|
| `admin/` | المسؤول: المواد/الشعب/الجدول، الطلاب، الدكاترة، عرض QR لكل دكتور، يستلم الحضور تلقائيًا، التقارير، نسخة احتياطية |
| `doctor/` | الدكتور: يمسح QR **مرة واحدة**، فيصله اسمه ومواده وشعبه وطلابه تلقائيًا، ثم يسجّل الحضور بـ NFC ويُرفع تلقائيًا |
| `student/` | الطالب: يكتب كوده مرة واحدة ثم يقرّب هاتفه من هاتف الدكتور |
| `core/` | الأكواد، التشفير، البروتوكول، الاقتران (QR)، الترحيل |
| `tools/` | `CoreReference.java` (نسخة مرجعية)، و`relay-test/` (اختبارات المزامنة مقابل خادم يحاكي Firebase) |

## التدفق
1. **المسؤول** (مرة واحدة): يلصق عنوان قاعدة Firebase في تبويب «الدكاترة» (الإعداد أدناه).
2. **المسؤول وحده يحدّد كل شيء:** المواد والشعب، **جدول المحاضرات** (اليوم، من، إلى، القاعة — زر «＋ موعد» تحت كل مادة)، أسماء الطلاب، وأسماء الدكاترة وموادهم. لا يستطيع الدكتور تعديل أي منها من تطبيقه. الطلاب يستلمون **أكوادهم** (12 خانة).
3. **الدكتور — مرة واحدة فقط:** المسؤول يضغط «عرض QR» عند اسمه، والدكتور يفتح تبويب «المواد» ← «مسح QR» ويصوّره.
4. من هنا **كل شيء تلقائي** كلما اتصل أي هاتف بالإنترنت (فتح التطبيق، أو عودة الاتصال، أو كل ~15 دقيقة في الخلفية):
   - أي تعديل عند المسؤول (اسم الدكتور، مادة أو شعبة جديدة، **موعد جديد أو محذوف**، طالب جديد/معدَّل) يصل لهاتف الدكتور.
   - عند الدكتور: يرى مواعيد كل مادة، وفي تبويب «مباشر» يظهر «حسب الجدول الآن» مع زر **بدء محاضرة الآن** (مدتها حتى نهاية الموعد). ويصل الطالب جدول مواده مع بياناته عند أول تقريب.
   - المسؤول يُنبَّه إن تداخلت محاضرتا دكتور واحد أو شُغلت قاعة بنفس الوقت (تنبيه فقط، لا منع).
   - حضور الدكتور يُرفع للمسؤول ويظهر في التقارير، ويظهر عند المسؤول «✓ مرتبط ومحدَّث» أو «⏳ لم يمسح QR بعد».
5. **أول تقريب** بين الطالب والدكتور: يثبت الطالب معرفته بكوده (HMAC) وحيازته لهاتفه (توقيع ECDSA من Keystore) فيرتبط جهازه بهويته.

## إعداد قاعدة Firebase (5 دقائق، مجاني، مرة واحدة)
1. افتح console.firebase.google.com ← **Add project** (يمكن تعطيل Analytics).
2. من القائمة: **Build ← Realtime Database ← Create Database** ← اختر أقرب موقع ← **Start in locked mode**.
3. تبويب **Rules** والصق التالي ثم **Publish**:
```json
{ "rules": { ".read": false, ".write": false,
    "m": { "$id": { ".read": true, ".write": true } } } }
```
   معناها: لا أحد يستطيع تصفّح القاعدة؛ الوصول فقط لمن يعرف رقم صندوق بريد عشوائي (128 بت) لا يعرفه إلا المسؤول ودكتوره، وما فيه مشفّر أصلًا.
4. تبويب **Data**: انسخ العنوان أعلاه، مثل `https://اسم-مشروعك-default-rtdb.firebaseio.com` (أو `...firebasedatabase.app`).
5. في تطبيق المسؤول ← «الدكاترة» ← الصق العنوان ← «حفظ».

> الخطة المجانية (Spark) تكفي بكثير: 1 جيجابايت تخزين و10 جيجابايت تنزيل شهريًا، والبيانات هنا بالكيلوبايت.

## الحماية
- ما يمرّ عبر Firebase: AES-256-GCM بمفتاح مشتق من كود الدكتور (PBKDF2 بـ100 ألف تكرار)، وأي تعديل بايت يُفشل الفتح. Firebase/Google لا ترى أسماء ولا أرقامًا.
- كود الدكتور لا يُكتب ولا يُرسل برسالة: يُمسح من QR فقط. **لا تصوّر QR لأحد غير الدكتور المعني.**
- الكشف الذي يصل الدكتور يحتوي «وسم» الطالب ومفتاحًا مشتقًا من كوده، لا الكود نفسه.
- كل لمسة NFC فيها nonce جديد ووقت من ساعة الدكتور ← لا إعادة إرسال. الكود مرتبط بجهاز واحد (غيره: `KEY_MISMATCH`).
- تنبيه في التقارير عند ظهور طالب بجهازين (كود مشارَك). قيد UNIQUE(sessionId, studentId) يمنع التكرار.

## إدارة الدكاترة
- **هاتف دكتور ضاع أو تغيّر:** «إلغاء الربط (QR جديد)» عند اسمه ← يُولَّد كود وصندوق جديدان ويُمحى القديم، ثم يمسح الدكتور QR الجديد (الحضور السابق محفوظ عند المسؤول).
- هاتف دكتور مرتبط بدكتور آخر لا يقبل QR مختلفًا إلا بعد «فك الارتباط ومسح البيانات» (يُرفع الحضور قبله).

## مهم للمسؤول
**هاتف المسؤول هو المرجع الوحيد؛ إن ضاع ضاعت الأكواد.** من تبويب التقارير: «إنشاء نسخة احتياطية مشفّرة»، واحفظ الملف خارج الهاتف وكوده منفصلًا. الاستعادة على هاتف جديد تعيد كل شيء ثم تتزامن.

## ما تم التحقق منه فعليًا
- `core` يُجمَّع بـ kotlinc 1.9.24 وتنجح اختبارات `CoreTest.kt` (17/17، يشمل صيغة الوقت والجدول) بتشغيلها فعليًا.
- `tools/relay-test`: عميل الترحيل + `AdminSync` (الكود الحقيقي) مقابل خادم يحاكي Firebase: **22 + 29 اختبارًا ناجحًا**، منها وصول الجدول وتعديله وحذفه إلى الدكتور المعني فقط، و نشر الكشف دون تكرار، وصول تعديل الاسم/الشعبة/الطالب، إشعار الاستلام، دمج الحضور دون تكرار، رفض ملف بكود آخر، انقطاع الإنترنت، إلغاء الربط، و30 تعديلًا متزامنًا مع 4 مزامنات دون ضياع.
- كود أندرويد (واجهات Compose، Room، WorkManager، الكاميرا، NFC) **لم يُجمَّع ولم يُجرَّب على جهاز** هنا؛ فُحصت أجزاء المنطق (`AdminVM` و`DoctorVM` و`DoctorSync`) بمجمّع Kotlin مقابل `android.jar` ومحاكيات صغيرة لـ Room.
  أول بناء على GitHub قد يكشف أخطاء تجميع صغيرة في ملفات الواجهة؛ أرسلها لي وأصلحها.

## غير منفَّذ بعد
- بديل QR/Nearby لحضور الأجهزة بلا HCE.
- الاختبار على أجهزة حقيقية (NFC بين هاتفين، كاميرا، المزامنة في الخلفية).
